# 工作流与迭代复盘

本页以原始阶段汇报、脚本及成员实践记录为依据，区分当时发生的迭代与复盘后的改进建议。工具结论仅适用于当时的具体任务和使用条件。

## 生产环节与协作交接

| 环节 | 输入 | 主要动作 | 输出／交接 |
| --- | --- | --- | --- |
| 内容策划 | 文化题材、同类作品、展示反馈 | 明确故事目标与核心场景 | 叙事框架、脚本 |
| 镜头准备 | 场景意图、参考画面 | 拆解主体、动作、风格和运镜需求 | 图片与提示词 |
| 图像生成 | Prompt、文化及视觉参照 | 试用工具，调整人物与场景 | 候选图像 |
| 视频生成 | 图像与动态描述 | 文生视频、图生视频、多主体尝试 | 候选片段 |
| 配乐生成 | 音乐创作需求 | 使用 AI 生成音乐 | 配乐素材，交由后期整合 |
| 人工检查 | 候选片段与脚本 | 检查逻辑、主体、风格及稳定性 | 可用素材或返工意见 |
| 剪辑交付 | 已选片段、声音、字幕 | 排序、转场、声音与任务提示整合 | 阶段 Demo、最终视频 |
| 展示复盘 | Demo 与反馈 | 调整剧情、风格和生成策略 | 下一轮修改任务 |

这是一套人工组织的多工具内容生产流程。视觉制作涉及即梦、LiblibAI、可灵和 Midjourney 等工具，分别承担图像、海报或动态片段任务；配乐由 AI 生成，最终整合由成员人工剪辑。原始分工文档明确要求成员在周三晚提交视频片段、随后于周四中午完成剪辑，说明片段生产与后期整合按依赖顺序推进。

## 案例 A：从场景拼接到任务驱动

**原始问题：**早期穿越叙事与景色组合缺少情节张力；引入简单任务后，又出现任务和剧情脱节。

**已发生的动作：**在分工讨论中提出“完成任务才能返回现实”的构思，把市井、茶百戏与学府内容连起来。后续脚本加入任务提示、工具与回归情节，最终答辩继续总结了故事结构的迭代。

**产品判断：**观众需要知道“为什么看这个场景”和“完成后会怎样”。任务机制的价值在于组织观看路径，不能只增加提示框而不改变剧情关系。

**结果边界：**最终成片可以看到任务与工具提示，但尚无观众理解度测试，不能将叙事调整直接写成完播率或留存提升。

## 案例 B：复杂穿越动作没有按指令生成

**原始问题：**希望人物触碰古画后被吸入画中，模型却生成人物蹲下；其他试验还出现民国服饰和错误的书法画面。

**已发生的动作：**成员从泛化的“年轻男大学生、2D 或 3D”逐步补充白衬衫、展厅、触碰动作、人物侧脸等描述。脚本中也保留了无法直接实现古画动态转场时的简化方案。

**复盘判断：**一个镜头同时要求复杂动作、空间转换和时代切换，会增加结果不可控性。更细致的描述有助于澄清意图，但不保证复杂动作一定生成成功。

**进一步建议：**将触碰、光效、进入新场景拆为单独镜头，通过剪辑衔接。此项是复盘建议，不将其写成原始记录中已完成的标准流程。

## 案例 C：古画运镜的稳定性不足

**原始问题：**希望表现沿山水向前行进的纵深感，生成结果更倾向于平移。旋转、万花筒过渡、航拍等尝试中出现图形不稳定和抖动。

**已发生的动作：**改变运镜方式，比较生成结果，记录效果的不确定性。

**产品判断：**某一次“生成得好看”不足以证明该方案适合作为稳定制作路径。对小团队而言，生成可控性、重试成本和剪辑可用性都需要参与取舍。

**结果边界：**保留这些问题作为工具能力探索的证据，不宣称通过某条 Prompt 已解决稳定性问题。

## 案例 D：海报工具的任务级选型

**我的直接实践：**试用可画、Midjourney 和即梦。项目记录中，可画产出未达到预期，Midjourney 在插画表现上较好，但中文字体生成较难控制；即梦在本次中文标题任务中更合适，随后继续修正文字。

**决策依据：**海报必须同时满足题材表达和标题可读性。将工具输出放进实际使用场景，才能做出选择。

**结果边界：**这是实际制作中的定性试用，不是统一样本量、模型版本和评分规则下的量化基准测试。

## 案例 E：风格一致性与文化细节

原始分工提出统一画风，脚本又讨论了从 2—2.5D 向仿真风格探索。最终视频仍可看到写实与插画片段切换，说明这个问题得到持续关注，但没有完全解决。

部分实验提示词还混用了不同朝代的人物与场景。这提示后续制作需要把“视觉参考”和“历史语境”分开检查，避免把生成图像的视觉可信度当成史实准确性。

**进一步建议：**为每个角色固定参考图，为场景建立时代与器物检查项，并记录返工原因。以上为后续改进方向。
